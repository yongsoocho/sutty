# Sutty v0.1.0 Alpha 4

> **Candidate only / 후보 전용:** `v0.1.0-alpha.4` tag와 공개 GitHub Release가 생성되기 전에는 이 문서가 릴리스 완료를 의미하지 않습니다. 아래 파일은 승격 성공 시 공개할 계획 자산입니다.

> The `v0.1.0-alpha.4` tag and public GitHub Release must exist before this becomes a published release note. Until then, the files below are planned promotion assets.

Alpha 4는 구현 여부와 실제 환경 인수, 공개 패키지 출시 상태를 분리하고, 검토 가능한 실환경 증거와 정확한 릴리스 산출물 연결을 위한 기준선을 추가하는 알파 후보입니다.

Alpha 4 is a candidate that separates source implementation, real-environment acceptance, and released-package status, and adds the foundation for reviewable live evidence and exact release-artifact provenance.

## 주요 변경 / Highlights

- Connection Doctor가 입력 검증부터 DNS·TCP, route, SSH handshake, Host Key, 인증, PTY, SFTP, forwarding까지 9개 연결 진단 단계를 안정적 Error Code·사용자 조치·비식별 요약으로 표시합니다.<br>Connection Doctor presents nine connection-diagnostic stages—from input validation through DNS/TCP, routing, SSH handshake, host key, authentication, PTY, SFTP, and forwarding—with stable error codes, user actions, and a de-identified summary.
- Known Hosts Manager가 최초 신뢰·마지막 사용 시각과 활동 기록을 보여주며, 변경된 Host Key는 기존·새 algorithm/fingerprint 비교, 독립 확인, 필수 사유, 원자적 compare-and-swap rotation을 거쳐야 합니다.<br>Known Hosts Manager shows first-trusted/last-used times and local activity; a changed host key requires old/new algorithm and fingerprint comparison, independent verification, a reason, and atomic compare-and-swap rotation.
- 사용자가 만드는 Support Bundle은 대상 SSH 연결을 화면에서 먼저 선택·확인하고 해당 진단 Event snapshot에 생성을 결속한 뒤 정확히 `manifest.json`과 `report.json`만 저장합니다. Session 이름과 Endpoint는 미리보기에만 있으며 ZIP에는 들어가지 않고, 저장 중 snapshot 변경과 오류 코드 계약 불일치는 기본 차단합니다.<br>The user-created Support Bundle previews the selected SSH connection, binds creation to that diagnostic-event snapshot, and stores exactly `manifest.json` and `report.json`. Session labels and endpoints remain UI-only; snapshot changes during save and conflicting diagnostic-code sources fail closed.
- 상세 Connection Log에는 인프라 식별 정보가 포함될 수 있음을 상시 경고하고 복사 동작을 원시 로그 복사로 명확히 표시합니다. `Alt+1`…`Alt+7` 내비게이션 accelerator는 처리 완료 상태로 종료해 Windows 미처리 키음을 억제합니다.<br>Detailed Connection Logs carry a persistent infrastructure-identifier warning and an explicit raw-copy label. The `Alt+1`…`Alt+7` navigation accelerators finish as handled to suppress the Windows unhandled-key sound.
- PR 본문 Gate가 사용자 문제·범위·제외 범위·수명주기·Secret 영향·테스트·실환경 검증·Requirement ID·Definition of Done을 검사하며 본문 수정 시 다시 실행됩니다.<br>A pull-request body gate checks the user problem, scope, exclusions, lifecycle, secret impact, tests, live validation, requirement IDs, and Definition of Done, and reruns when the body is edited.
- 호환성 주장을 **Implemented**, **Live Validated**, **Released**, **Unsupported** 네 상태로 제한하고 Windows/architecture, SSH 인증·키, route·forwarding, terminal, SFTP의 주장 경계를 문서화했습니다.
- `manifest.yml`과 redacted `summary.json`으로 구성된 엄격한 실환경 증거 계약, secret·endpoint·경로·transcript 유출 방지 검사, 정상·오류 fixture를 추가했습니다.
- 실서버 harness에 증거 bundle 작성 경로를 연결했습니다. 부분 자동화 결과는 전체 인수로 오인되지 않도록 `Blocked`로 남고, 완전한 gate와 사람의 redaction 검토가 끝난 결과만 호환성 상태를 올릴 수 있습니다.
- 정식 run은 항상 검토 전 bundle을 만들며, 사람이 전체 파일을 확인한 뒤 원본 hash를 묶는 새 write-once `review.json` bundle만 인수할 수 있습니다. 기존 committed bundle의 수정·삭제·rename은 append-only history guard가 거부합니다.
- Candidate는 read-only token에 보이는 GitHub `main`/`v*` ruleset 의미를 조회합니다. 실제 release promotion은 보호 환경의 별도 ruleset-audit token으로 bypass actor까지 두 번 strict 검사하며, PR 경계·필수 5개 검사·force-push/tag 이동 차단이 없으면 실패합니다.
- Alpha 4 실행 순서를 Direct 비밀번호 기준선부터 키·Agent·MFA, 간접 route, forwarding, fault, connection information, 정확한 package mapping까지 의존성 기준으로 고정했습니다.
- source, package SHA-256, Windows build/architecture, 정제한 server family/version, route, authentication, 선언한 scenario가 모두 같은 exact tuple에서만 결과를 적용하도록 범위를 제한했습니다.

## 검증 경계 / Validation boundary

- 위 제품 기능은 현재 소스 후보의 구현 범위이며, 새 exact Candidate ZIP의 `PKG-001`, `SSH-LIVE-001`, 사람의 Evidence 검토를 대체하지 않습니다.
- 제품 Support Bundle(`manifest.json`, `report.json`)은 로컬 장애 지원용입니다. Release 인수용 Live Evidence Bundle(`manifest.yml`, `summary.json`, 검토 후 `review.json`)과 별개이며 서로 대신 사용할 수 없습니다.
- `Alt+1`…`Alt+7` 키음 억제는 소스 경로에 반영됐지만 exact x64 Candidate의 실제 Windows UI에서 수동 확인해야 합니다.
- x64와 ARM64는 locked restore, Release build, self-contained publish, payload policy, archive inventory와 payload별 entry 내용 동일성, release metadata, SHA-256 검사의 대상입니다.
- ARM64는 build/package 경로만 검증되며 실제 ARM64 Windows 실행이나 호환성을 주장하지 않습니다.
- Test-owned Docker OpenSSH의 Direct+Password 실행도 규격에 맞는 `Pass` bundle과 사람의 redaction 검토가 완료되기 전에는 **Live Validated** 또는 **Released**로 주장하지 않습니다.
- 간접 route, local/remote/dynamic forwarding, Agent, MFA, key-format matrix, terminal/tool matrix, 대용량 SFTP, fault/soak 조합은 이번 릴리스의 실환경 호환성 주장에 포함되지 않습니다.

- x64 and ARM64 are subject to locked restore, Release build, self-contained publish, payload-policy, archive-inventory and per-entry content identity, release-metadata, and SHA-256 checks.
- ARM64 receives build/package validation only; this release makes no claim of a real ARM64 Windows run or compatibility.
- A Direct+Password run against test-owned Docker OpenSSH is not claimed as **Live Validated** or **Released** until a conforming `Pass` bundle receives human redaction review.
- Indirect routes, local/remote/dynamic forwarding, Agent, MFA, the key-format matrix, terminal/tool matrix, large-scale SFTP, and fault/soak combinations are outside this release's live-compatibility claims.
- The product features above describe the current source candidate; they do not replace `PKG-001`, `SSH-LIVE-001`, or human evidence review against newly generated exact Candidate ZIPs.
- The product Support Bundle (`manifest.json`, `report.json`) is for local troubleshooting. It is separate from, and cannot substitute for, a release-acceptance Live Evidence Bundle (`manifest.yml`, `summary.json`, and post-review `review.json`).
- The `Alt+1`…`Alt+7` sound suppression is implemented in source and still requires a manual check in the exact x64 Candidate on Windows.

## Alpha 제한 / Alpha limitations

- Windows 11 24H2 이상만 제품 대상입니다.
- ZIP은 코드 서명되지 않았으며 MSIX 설치 패키지가 아닙니다.
- 공개 ZIP과 checksum이 있다는 사실만으로 어떤 환경 행도 **Released**가 되지 않습니다. 정확한 package SHA-256과 commit이 검토 완료된 실환경 bundle에 연결돼야 합니다.
- 목록에 없는 환경·서버·인증·경로·워크로드 조합에는 지원 주장이 없습니다.
- 중요한 운영 서버의 유일한 접속·복구 도구로 사용하지 마세요.

This Alpha is for personal evaluation and development/test/staging pilots. It is not GA and does not make a broad compatibility claim.
