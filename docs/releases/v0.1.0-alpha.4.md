# Sutty v0.1.0 Alpha 4

> **Candidate only / 후보 전용:** `v0.1.0-alpha.4` tag와 공개 GitHub Release가 생성되기 전에는 이 문서가 릴리스 완료를 의미하지 않습니다. 아래 파일은 승격 성공 시 공개할 계획 자산입니다.

> The `v0.1.0-alpha.4` tag and public GitHub Release must exist before this becomes a published release note. Until then, the files below are planned promotion assets.

Alpha 4는 Windows PowerShell/CMD 중심 작업 공간, 반응형 보조 패널, 파일 작업과 로컬 연결 실행기를 확장한 알파 후보입니다. 구현 여부와 실제 환경 인수, 공개 패키지 출시 상태는 별도로 기록합니다.

Alpha 4 expands the Windows PowerShell/CMD workspace, responsive supporting panes, file workflows, and local connection launcher. Source implementation, real-environment acceptance, and published-package status remain separate.

## 주요 변경 / Highlights

- 중앙 작업 공간은 실제 PowerShell/CMD ConPTY 또는 SSH PTY 셸을 유지합니다. Home·Hosts·Transfers·Commands는 넓은 창의 오른쪽, 논리 픽셀 1100 미만 창의 아래에 열립니다. Settings만 셸을 가리는 전체 페이지이며 열린 세션은 계속 실행됩니다. 탭을 바꿔도 선택한 보조 패널을 유지하고 카드·도구 모음·파일 패널은 너비에 맞춰 재배치합니다.<br>The central workspace keeps a real PowerShell/CMD ConPTY or SSH PTY shell. Home, Hosts, Transfers, and Commands open on the right in wide windows and below the terminal under 1100 logical pixels. Settings covers the shell as a full page while sessions keep running. Switching shell tabs preserves the selected supporting pane, and cards, toolbars, and file panes adapt to width.
- `+`와 `Ctrl+T`에서 **New SSH connection**, **Open saved host**, **Local PowerShell**, **Local CMD**, **Import hosts**를 선택합니다. 새 시작과 마지막 탭 종료 뒤에는 PowerShell을 열며 선택형 작업 공간 복원은 로컬 탭별 셸 종류를 기억합니다. Quick Connect는 일반 연결 필드를 먼저 보여주고 일회성 Host 저장은 연결 성공 뒤에 제안합니다.<br>`+` and `Ctrl+T` offer **New SSH connection**, **Open saved host**, **Local PowerShell**, **Local CMD**, and **Import hosts**. A fresh start and closing the last tab open PowerShell; optional workspace restoration preserves each local tab's shell choice. Quick Connect leads with ordinary connection fields and offers to save one-off hosts after a successful connection.
- `CONPTY` / `PTY` 크기 옆의 복사 아이콘은 오류를 포함한 마지막 명령의 표시 출력을 복사합니다. PowerShell/CMD의 실행 중 프롬프트 표시자는 프로필 파일을 수정하지 않습니다. 탭·제어 문자·줄바꿈은 PTY가 처리한 텍스트이며 사용자 정의 또는 표시자가 없는 SSH 셸의 명령 경계는 최선 방식으로 판별합니다.<br>The copy icon beside the `CONPTY` / `PTY` dimensions copies the latest rendered command output, including errors. PowerShell/CMD use runtime prompt markers without editing profile files. The copied text reflects PTY processing of tabs, controls, and newlines; custom or unmarked SSH command boundaries are best effort.
- [36개 앱·터미널 테마](https://github.com/yongsoocho/sutty/blob/v0.1.0-alpha.4/docs/THEMES.md)에 VS Code Dark+/Light+, Dracula, Monokai, Nord, Tokyo Night, Catppuccin 등을 추가했습니다. 그라데이션 강조를 유지하며 터미널의 **앱 테마에 맞춤**은 선택한 이름의 배경·전경·ANSI 색상을 적용합니다. 설정의 숫자는 증감 버튼 없이 직접 입력합니다.<br>[36 app and terminal themes](https://github.com/yongsoocho/sutty/blob/v0.1.0-alpha.4/docs/THEMES.md) include VS Code Dark+/Light+, Dracula, Monokai, Nord, Tokyo Night, and Catppuccin. Gradient accents remain, and **Follow application** applies the selected named background, foreground, and ANSI palette. Numeric settings use direct input without spin buttons.
- Settings → About에 빨간색 **설정 초기화**와 **SQLite 초기화**를 추가했습니다. 각각 기본 선택이 No인 Yes/No 확인 뒤에만 실행합니다. 설정은 기본값을 원자적으로 저장하고 즉시 적용하며, SQLite 초기화는 트랜잭션 안에서 사용자 데이터만 지우고 스키마·마이그레이션 정보를 보존합니다. 열린 세션과 별도 설정·키 신뢰·금고·전송 복구 파일은 SQLite 초기화로 닫거나 삭제하지 않습니다.<br>Settings → About adds red **Reset settings** and **Reset SQLite data** actions, each requiring a Yes/No dialog that defaults to No. Settings reset atomically saves and applies defaults; SQLite reset clears user data transactionally while preserving schema and migration metadata. SQLite reset keeps open sessions and separate settings, trust, vault, and transfer-recovery files.
- **Multi Command**를 별도 내비게이션 항목과 `Alt+8`로 열 수 있습니다. 기본 선택은 0개이고 체크한 세션에만 실행하며 PROD 대상의 추가 확인을 유지합니다. Broadcast 입력 아래에 실행 버튼을 배치하고 SSH·로컬 상태를 구분합니다.<br>**Multi Command** has its own navigation destination and `Alt+8` shortcut. It starts with zero targets, runs only on checked sessions, and retains the additional PROD-target confirmation. The run button sits below the broadcast input, with SSH and local session states distinguished.
- Transfers의 파일 탐색은 선택한 셸만 따릅니다. SSH는 같은 세션의 Files를 사용하고 PowerShell/CMD는 프롬프트가 알린 현재 폴더를 표시합니다. 셸이나 경로가 없으면 안내를 보여주며 임의의 다른 서버를 선택하지 않습니다. Local/Remote Files는 절대 경로·뒤로/앞으로·상위 폴더·정렬·숨김 항목·원격 즐겨찾기·다중 선택을 제공합니다. Pane 간 파일/폴더 드래그와 탐색기 → Remote 드롭은 원본을 남기는 복사이며 기존 충돌·staging·checkpoint·검증 경로를 사용합니다.<br>The Transfers browser follows only the selected shell: SSH reuses that session's Files, and PowerShell/CMD show the current directory reported at the prompt. Missing shells or paths show an explanation without selecting another server. Local/Remote Files offer absolute paths, back/forward, parent navigation, sorting, hidden files, remote favorites, and multi-selection. Pane-to-pane file/folder drag and Explorer-to-Remote drop copy while retaining sources through the existing collision, staging, checkpoint, and verification flow.
- 원격 일반 텍스트 파일은 설정한 외부 편집기에서 열 수 있습니다. 8 MiB 한도, 기본 수동 업로드, 파일별 선택형 자동 업로드, 크기·시각 충돌 확인, 불변 업로드 복사본과 로컬 복구 파일을 사용합니다. 호스트·태그·경로·터널·명령 정의의 로컬 JSON 공유는 미리보기와 항목별 선택을 거치며 자격증명·키 경로·신뢰·기록을 제외합니다.<br>Regular remote text files can open in a configured external editor, with an 8 MiB limit, manual upload by default, per-file opt-in automatic upload, size/time conflict checks, immutable upload snapshots, and retained local recovery copies. Local JSON sharing of host, tag, route, tunnel, and command definitions uses previews and per-item choices while excluding credentials, key paths, trust, and history.
- Home의 한 줄 연결은 `ssh worker1` 또는 `multipass connect master` 같은 허용된 직접 실행 파일을 로컬 터미널에 엽니다. 현재 PC의 PATH·SSH 설정·Agent를 사용하고 즐겨찾기와 최근 명령을 SQLite에 보관합니다. 셸 연결·리디렉션·명령 인터프리터와 자격증명 형태 인자는 거부하고 종료한 명령은 자동 재실행하지 않습니다.<br>Home's one-line connection launcher opens allowed direct executables such as `ssh worker1` or `multipass connect master` in a local terminal. It uses the current PC's PATH, SSH configuration, and Agent, and stores favorites and recent commands in SQLite. Shell chaining, redirection, command interpreters, and credential-shaped arguments are rejected; finished commands are never replayed automatically.
- 전역 Transfer Center를 영속 큐의 실시간 제어면으로 바꿨습니다. 상태·방향·대상 필터와 완료 기록 제거를 제공하고, 정확히 일치하는 연결된 Files 실행자가 받을 수 있을 때만 일시정지·재개·실패 대상 재시도·취소를 활성화합니다. 큐 변경과 대상 실행은 OS 파일 lock/lease로 여러 Sutty 프로세스 사이에서도 직렬화합니다. Multi batch는 전역 화면에 표시하지만 batch 전체 Pause/Cancel은 아직 제공하지 않습니다.<br>The global Transfer Center is now a live control surface for the durable queue. It filters by state, direction, and target, removes completed records, and enables Pause, Resume, failed-target Retry, and Cancel only when the exact connected Files executor can accept them. Operating-system file locks and leases serialize queue mutation and target execution across Sutty processes. Multi batches are visible, but batch-wide global Pause/Cancel is not available yet.
- 실패하거나 끊긴 SSH 세션에 새 Shell을 만드는 수동 재연결을 추가했습니다. 저장 Host는 최신 profile과 선택형 Vault 비밀값을 다시 읽고, 일회성 세션은 비밀값 없는 연결 초안을 Quick Connect에서 확인하게 합니다. 이전 명령·터미널 입력·transport·이번만 신뢰 결정은 재실행하거나 재사용하지 않습니다. 자동 재연결과 SFTP·tunnel 자동 복구는 아직 포함하지 않습니다.<br>Failed or disconnected SSH sessions now offer a manual reconnect that creates a fresh shell. Saved Hosts reload the latest profile and optional vault secret; one-off sessions return a credential-free draft to Quick Connect for review. Previous commands, terminal input, transports, and trust-once decisions are never replayed or reused. Automatic reconnect and automatic SFTP/tunnel recovery are not included yet.
- 세션의 Tunnels는 Local·Remote·Dynamic 규칙 추가와 시작/중지, 실제 수신 상태와 오류를 표시합니다. 새 규칙은 loopback을 기본값으로 사용하고 외부 바인드 시작을 확인받으며 세션 종료 시 정리합니다. 사용하지 않는 `systemAIModels`·LockScreen manifest 선언도 제거했습니다.<br>Session Tunnels supports adding and starting/stopping Local, Remote, and Dynamic rules with real listener states and errors. New rules default to loopback, starting an external bind requires confirmation, and listeners close with the session. Unused `systemAIModels` and LockScreen manifest declarations were removed.
- Connection Doctor가 입력 검증부터 DNS·TCP, route, SSH handshake, Host Key, 인증, PTY, SFTP, forwarding까지 9개 연결 진단 단계를 안정적 Error Code·사용자 조치·비식별 요약으로 표시합니다.<br>Connection Doctor presents nine connection-diagnostic stages—from input validation through DNS/TCP, routing, SSH handshake, host key, authentication, PTY, SFTP, and forwarding—with stable error codes, user actions, and a de-identified summary.
- Known Hosts Manager가 최초 신뢰·마지막 사용 시각과 활동 기록을 보여주며, 변경된 Host Key는 기존·새 algorithm/fingerprint 비교, 독립 확인, 필수 사유, 원자적 compare-and-swap rotation을 거쳐야 합니다.<br>Known Hosts Manager shows first-trusted/last-used times and local activity; a changed host key requires old/new algorithm and fingerprint comparison, independent verification, a reason, and atomic compare-and-swap rotation.
- 사용자가 만드는 Support Bundle은 대상 SSH 연결을 화면에서 먼저 선택·확인하고 해당 진단 Event snapshot에 생성을 결속한 뒤 정확히 `manifest.json`과 `report.json`만 저장합니다. Session 이름과 Endpoint는 미리보기에만 있으며 ZIP에는 들어가지 않고, 저장 중 snapshot 변경과 오류 코드 계약 불일치는 기본 차단합니다.<br>The user-created Support Bundle previews the selected SSH connection, binds creation to that diagnostic-event snapshot, and stores exactly `manifest.json` and `report.json`. Session labels and endpoints remain UI-only; snapshot changes during save and conflicting diagnostic-code sources fail closed.
- 상세 Connection Log에는 인프라 식별 정보가 포함될 수 있음을 상시 경고하고 복사 동작을 원시 로그 복사로 명확히 표시합니다. `Alt+1`…`Alt+7` 내비게이션 accelerator는 처리 완료 상태로 종료해 Windows 미처리 키음을 억제합니다.<br>Detailed Connection Logs carry a persistent infrastructure-identifier warning and an explicit raw-copy label. The `Alt+1`…`Alt+7` navigation accelerators finish as handled to suppress the Windows unhandled-key sound.
- PR 본문 Gate가 사용자 문제·범위·제외 범위·수명주기·Secret 영향·테스트·실환경 검증·Requirement ID·Definition of Done을 검사하며 본문 수정 시 다시 실행됩니다.<br>A pull-request body gate checks the user problem, scope, exclusions, lifecycle, secret impact, tests, live validation, requirement IDs, and Definition of Done, and reruns when the body is edited.
- 호환성 주장을 **Implemented**, **Live Validated**, **Released**, **Unsupported** 네 상태로 제한하고 Windows/architecture, SSH 인증·키, route·forwarding, terminal, SFTP의 주장 경계를 문서화했습니다.
- `manifest.yml`과 redacted `summary.json`으로 구성된 엄격한 실환경 증거 계약, secret·endpoint·경로·transcript 유출 방지 검사, 정상·오류 fixture를 추가했습니다.
- 실서버 harness에 증거 bundle 작성 경로를 연결했습니다. 부분 자동화 결과는 전체 인수로 오인되지 않도록 `Blocked`로 남고, 완전한 gate와 사람의 redaction 검토가 끝난 결과만 호환성 상태를 올릴 수 있습니다.
- 정식 run은 항상 검토 전 bundle을 만들며, 사람이 전체 파일을 확인한 뒤 원본 hash를 묶는 새 write-once `review.json` bundle만 인수할 수 있습니다. 기존 committed bundle의 수정·삭제·rename은 append-only history guard가 거부합니다.
- Candidate는 read-only token에 보이는 GitHub `main`/`v*` ruleset 의미를 조회합니다. 실제 release promotion은 보호 환경의 별도 ruleset-audit token으로 bypass actor까지 두 번 strict 검사하며, PR 경계·필수 검사·force-push/tag 이동 차단이 없으면 실패합니다.
- Alpha 4 실행 순서를 Direct 비밀번호 기준선부터 키·Agent·MFA, 간접 route, forwarding, fault, connection information, 정확한 package mapping까지 의존성 기준으로 고정했습니다.
- source, package SHA-256, Windows build/architecture, 정제한 server family/version, route, authentication, 선언한 scenario가 모두 같은 exact tuple에서만 결과를 적용하도록 범위를 제한했습니다.

## 검증 경계 / Validation boundary

- 위 제품 기능은 현재 소스 후보의 구현 범위이며, 새 exact Candidate ZIP의 `PKG-001`, `SSH-LIVE-001`, 사람의 Evidence 검토를 대체하지 않습니다.
- 제품 Support Bundle(`manifest.json`, `report.json`)은 로컬 장애 지원용입니다. Release 인수용 Live Evidence Bundle(`manifest.yml`, `summary.json`, 검토 후 `review.json`)과 별개이며 서로 대신 사용할 수 없습니다.
- `Alt+1`…`Alt+7` 키음 억제는 소스 경로에 반영됐지만 exact x64 Candidate의 실제 Windows UI에서 수동 확인해야 합니다.
- PowerShell/CMD·반응형 배치·테마·복사·초기화·Multi Command·현재 셸 파일 탐색과 패널 유지의 소스 구현은 exact Candidate의 Windows UI 인수를 대신하지 않습니다. **2026-09-22 화면 자동화는 사용자의 Escape 입력으로 중단**되었고 재빌드한 화면·수동 클립보드 인수를 완료하지 않았습니다.
- Pane 드래그, 원격 외부 편집, 정의 공유, 연결된 단일 Files 작업의 전역 제어와 수동 재연결은 구현됐지만 실제 Windows UI·실서버 인수는 미완료입니다. 동기 탐색·디렉터리 비교·자동 재연결·Multi batch 전체의 전역 Pause/Cancel은 구현하지 않았습니다.
- x64와 ARM64는 locked restore, Release build, self-contained publish, payload policy, archive inventory와 payload별 entry 내용 동일성, release metadata, SHA-256 검사의 대상입니다.
- ARM64는 build/package 경로만 검증되며 실제 ARM64 Windows 실행이나 호환성을 주장하지 않습니다.
- Test-owned Docker OpenSSH의 Direct+Password 실행도 규격에 맞는 `Pass` bundle과 사람의 redaction 검토가 완료되기 전에는 **Live Validated** 또는 **Released**로 주장하지 않습니다.
- 간접 route, local/remote/dynamic forwarding, Agent, MFA, key-format matrix, terminal/tool matrix, 대용량 SFTP, fault/soak 조합은 이번 릴리스의 실환경 호환성 주장에 포함되지 않습니다.

- x64 and ARM64 are subject to locked restore, Release build, self-contained publish, payload-policy, archive-inventory and per-entry content identity, release-metadata, and SHA-256 checks.
- ARM64 receives build/package validation only; this release makes no claim of a real ARM64 Windows run or compatibility.
- A Direct+Password run against test-owned Docker OpenSSH is not claimed as **Live Validated** or **Released** until a conforming `Pass` bundle receives human redaction review.
- Indirect routes, local/remote/dynamic forwarding, Agent, MFA, the key-format matrix, terminal/tool matrix, large-scale SFTP, and fault/soak combinations are outside this release's live-compatibility claims.
- The product features above describe the current source candidate; they do not replace `PKG-001`, `SSH-LIVE-001`, or human evidence review against newly generated exact Candidate ZIPs.
- The product Support Bundle (`manifest.json`, `report.json`) is for local troubleshooting. It is separate from, and cannot substitute for, a release-acceptance Live Evidence Bundle (`manifest.yml`, `summary.json`, and post-review `review.json`).
- The `Alt+1`…`Alt+7` sound suppression is implemented in source and still requires a manual check in the exact x64 Candidate on Windows.
- Source implementation of PowerShell/CMD, responsive panes, themes, copying, reset, Multi Command, the current-shell browser, and pane persistence does not replace exact-candidate Windows acceptance. **Windows UI automation on 2026-09-22 was stopped by the user's Escape input**, before acceptance of the rebuilt interface and manual clipboard interaction.
- Pane drag-and-drop, remote external editing, definition sharing, global controls for a connected single Files job, and manual reconnect are implemented but remain unverified through real Windows-UI and live-server acceptance. Synchronized browsing, directory comparison, automatic reconnect, and batch-wide global Multi Pause/Cancel remain unimplemented.
