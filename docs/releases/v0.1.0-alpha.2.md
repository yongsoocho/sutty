# Sutty v0.1.0 Alpha 2

제품 범위와 개발 실행 체계를 정리하고, 저장된 연결 경로 오류를 안전하게 진단·복구할 수 있도록 개선한 Alpha 2입니다.

Alpha 2 aligns the product scope and engineering workflow, and makes saved-route failures diagnosable and recoverable without silently opening a Direct connection.

## 주요 변경 / Highlights

- `Local`, `Terminal`, `REPL`, `Files`, `Multi` 5개 주 작업 공간과 `Saved Hosts`, `Commands` 2개 공통 기능으로 제품 구조를 통일했습니다.
- 개인·소규모 팀을 위한 local-first 범위, 비목표, 소규모 팀의 자격증명 없는 파일/Git 정의 공유 방식을 README와 제품 문서에 명시했습니다.
- `AuditContext`를 로컬 진단 상관관계 모델로 변경해 중앙 수집을 암시하는 용어를 제거했습니다.
- 저장 Route를 `Valid`, `Unsupported`, `Corrupt`로 분리하고 `SAVED_ROUTE_UNSUPPORTED`, `SAVED_ROUTE_CORRUPT` 오류 코드를 추가했습니다.
- 지원하지 않거나 손상된 저장 Route는 Direct로 조용히 연결되지 않으며, 원인과 Host 편집 복구 경로를 표시합니다.
- 기존 `enterpriseMode` 저장값은 계속 읽고 `DisableDirect`로 마이그레이션하며, 새 저장에는 현재 필드만 기록합니다.
- Core → Test → UI → Live validation 순서, 취소·종료·Secret·SFTP 무결성·Multi 안전 기준을 개발 Playbook과 PR/Issue 템플릿으로 고정했습니다.
- 제품 범위 검사에 마이그레이션 문서 allowlist, 과장 표현·폐기 기획 DOCX 차단, 9개 fixture 테스트를 추가했습니다.
- 현재 제품 정의와 충돌하는 과거 기획 DOCX 2개를 활성 문서 트리에서 제거했습니다.

## 검증 / Validation

릴리스 workflow는 태그와 소스 버전 일치, 제품 범위, x64·ARM64 Release build, 보안·Saved Host/History·터미널·설정·SFTP self-test, self-contained publish, payload 정책, ZIP SHA-256을 확인합니다.

The release workflow validates the tag/source version, product scope, x64 and ARM64 Release builds, security/Saved Host/History/terminal/settings/SFTP self-tests, self-contained publishing, payload policy, and ZIP SHA-256 checksums.

## Alpha 제한 / Alpha limitations

- Windows 11 24H2 이상만 지원합니다.
- ZIP은 코드 서명되지 않았으며 MSIX 설치 패키지가 아닙니다.
- 실제 서버의 Agent·MFA·Proxy·Jump·Forwarding 조합 검증과 Terminal shell/TUI/IME/soak 매트릭스는 진행 중입니다.
- 16개 실서버 장시간 실행, 100GB, 100,000개 파일 매트릭스는 아직 공식 완료되지 않았습니다.
- 중요한 운영 서버의 유일한 접속·복구 도구로 사용하지 마세요.

This Alpha is for personal evaluation and development/test/staging pilots. It is not a GA release or a mandatory deployment.
